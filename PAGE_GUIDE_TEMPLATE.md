# Page Guide Template

Duplicate this template for each page after the page inventory is agreed.

## Page name

## Purpose
What user need does this page serve?

## Primary user and entry points
Who uses it, and how do they arrive here?

## Main content hierarchy
List the content in display order. Separate essential information from optional/secondary information.

## Components
List shared and page-specific components. Reuse established components where the content type is the same.

## Actions and behaviour
For each action, state what happens next, whether authentication is needed, and what success/failure looks like.

## Data required
List fields the page needs. Mark fields as required, optional, or provisional. Do not invent data fields merely because they look useful.

## Navigation
Where can the user go from here? How do they return?

## Responsive behaviour
Explain mobile-first layout and what changes on wider screens.

## UI states
Loading, populated, empty, no results, error, unavailable, and authentication-required states as applicable.

## Acceptance criteria
List observable conditions that let the designer/developer verify the page is complete.

## Open assumptions
Record only decisions that actually block this page. Otherwise use a marked placeholder and continue.
