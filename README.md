# D'Voice project   documents

Start with these files in this order:

1. `PRODUCT_BRIEF.md` — the short explanation of what D'Voice is and what belongs in the MVP.
2. `PRODUCT_SPEC.md` — the expected product behaviour and requirements.
3. `IMPLEMENTATION_PLAN.md` — the sequence of work and checklists.
4. `SUCCESS_CRITERIA.md` — how to verify the product is ready.

**Current product boundary:** D'Voice is initially for FUTA and will not use multi-tenant architecture in the MVP. Academic utility remains the primary purpose. The founder page and WhatsApp community invitation are optional supporting features; administrators must be able to edit their content without code changes.

Keep these documents useful rather than ceremonial. Update them when a decision changes, and avoid duplicating long explanations across files.
