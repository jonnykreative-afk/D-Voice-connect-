# D'Voice planning and UI handoff

## Start here
1. `PRODUCT_BRIEF.md` — quick product overview and boundaries.
2. `PRODUCT_SPEC.md` — expected behaviour and initial page inventory.
3. `UI_HANDOFF.md` — instructions and deliverables for the UI designer/model.
4. `PAGE_GUIDE_TEMPLATE.md` — reusable template for page-level product guides.
5. `SUCCESS_CRITERIA.md` — how the MVP will be judged.
6. `IMPLEMENTATION_PLAN.md` — staged work checklist.

## Current decisions
- FUTA-only MVP; no multi-tenancy.
- Academic utility is the primary purpose.
- Faculty is the only confirmed personalisation attribute.
- Administrators publish announcements.
- Most resources are PDFs; metadata is shown/required only where it helps identify and discover a resource.
- Founder content is editable and can use marked placeholders during design.
- WhatsApp community purpose is provisional for design: D'Voice updates, useful opportunities, academic discussion/quizzes, and connecting students. Confirm actual activities, moderation, and invite URL before launch.
- Indigenous-group functionality is deferred until the list and use case are supplied.

## Handoff rule
Ask the UI designer/model to propose the page inventory, navigation, user journeys, and design system first. Review those outputs before generating detailed pages. Then complete page guides and build one page at a time.
